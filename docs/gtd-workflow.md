# GTD 工作流全面指南

## 什么是 GTD？

GTD（Getting Things Done）是由 David Allen 提出的时间管理方法论。核心理念：**把一切事情从大脑中移出，记录到可靠的外部系统中，让大脑专注于思考和执行。**

## GTD 五步工作流

### 1. 📥 收集 (Capture)

**规则：任何东西先进 Inbox，不加判断。**

- 新的想法？扔 Inbox
- 别人交代的任务？扔 Inbox
- 读到的好文章？扔 Inbox
- 想到的待办事项？扔 Inbox

**在 Douzi 中实现：**

```bash
# 最快方式：在看板 Inbox 列点击"+"
# 或者直接在文件中创建
cat > knowledge-base/gtd/inbox/2026-04-29-想法.md << 'TASK'
---
title: "想法标题"
status: "inbox"
priority: "P3"
created: 2026-04-29
tags: []
---

# 想法标题

详细描述...
TASK
```

### 2. 🔄 厘清 (Clarify)

**规则：定期处理 Inbox，对每个项目问：**

1. **它是什么？** — 明确具体内容
2. **它需要行动吗？**
   - ❌ 不需要 → 参考资料 / 丢弃
   - ✅ 需要 → 继续问
3. **它能在 2 分钟内完成吗？**
   - ✅ 是 → 立即执行
   - ❌ 否 → 继续问
4. **需要别人完成吗？**
   - ✅ 是 → 移到 `waiting_for/`
   - ❌ 否 → 继续问
5. **是多步骤项目吗？**
   - ✅ 是 → 创建项目文件到 `projects/`
   - ❌ 否 → 移到 `next_actions/`

**AI 帮你做这一步：**

- 点击看板右上角的 **「✨ 一键整理」** 按钮
- 或在终端运行 `node ai-process.mjs`

### 3. 🏗️ 组织 (Organize)

### 优先级体系

| 优先级 | 含义 | 处理时限 |
|--------|------|---------|
| P0 | 紧急且重要（火烧眉毛） | 立即处理 |
| P1 | 重要不紧急（核心任务） | 今日/本周 |
| P2 | 可做但不紧急 | 本周/下周 |
| P3 | 低优先级（有空再做） | 有空时 |

### 标签体系建议

- `AI/` — AI 相关任务
- `调研/` — 调研探索类
- `项目/` — 项目管理工作
- `学习/` — 知识技能学习
- `生活/` — 个人生活类
- `技术/` — 技术开发类

### 4. 👀 回顾 (Reflect)

**每日回顾：** 查看 `daily_review/` 目录中的复盘笔记，或使用 Web 看板的「每日回顾」标签页。

**回顾清单：**

- [ ] 清空 Inbox（处理或 AI 辅助处理）
- [ ] 查看 Next Actions 中今日需完成的项
- [ ] 检查 Waiting For 中是否有需跟催的
- [ ] 回顾 Projects 进度
- [ ] 查看 Done，将超过 7 天的归档
- [ ] 写今日复盘

### 5. ⚡ 执行 (Engage)

**选择下一个行动的依据：**

1. **情境** — 当前可用的时间和工具
2. **时间** — 当前可用时间是否足够
3. **精力** — 当前精力状态
4. **优先级** — 哪个任务最重要

---

## 任务生命周期

```
Inbox → (厘清/AI整理) → Next Actions / Waiting / Projects / Reference → Done → Archived
```

## 命名规范

```
YYYY-MM-DD-简短描述.md
```

示例：

- `2026-04-29-设计新的登录页面.md`
- `2026-04-29-调研竞品方案.md`
- `2026-04-29-AI搜Q2指标.md`
